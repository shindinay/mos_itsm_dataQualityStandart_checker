## 1. Услуга [АТ тест вапро. Бухгалтерия и кадры](https://community.itsm-qa.mos.ru/services/22195)

Соответствует: команда первой линии и команда поддержки заполнены, поставщик указан, владелец услуги указан, флажок «Отключено» снят.

Несоответствия:

1. **Несоответствие (Полнота):** поле «Ключевые слова» не заполнено.
   - **Предложение по исправлению:** добавить не менее двух ключевых слов, характеризующих услугу (например: «бухгалтерия», «кадры», «зарплата»). Не включать эти слова в имя и описание услуги.
2. **Несоответствие (Полнота):** поле «Описание» не заполнено.
   - **Предложение по исправлению:** заполнить описание так, чтобы клиент мог однозначно понять конечный результат оказания услуги (например: «Предоставление возможностей ведения бухгалтерии и кадрового учета в системе …»).
3. **Несоответствие (Точность, подозрение):** имя «АТ тест вапро. Бухгалтерия и кадры» — формат «наименование организации/подразделения + результат» выглядит допустимым («Конечный результат оказания услуги» / «Наименование из ГК»), но токен «АТ тест вапро» не выглядит как закрепленное наименование; рекомендуется подтвердить корректность имени у владельца услуги.
   - **Предложение по исправлению:** убедиться, что имя соответствует одному из трех допустимых синтаксисов стандарта и уникально среди услуг других Поставщиков.

Примечания (контролируемые поля, не критичные для активной тестовой услуги): менеджер релиза, менеджер изменения, менеджер базы знаний, менеджер проблемы, менеджер доступности, менеджер мощностей, менеджер по непрерывности — не заполнены. Стандарт требует для них активных записей из справочника «Лица» с sAMAccountName; при вводе услуги в промышленную эксплуатацию — заполнить.

## 2. Компоненты услуги

### 2.1 [АТ тест вапро. Бухгалтерия и кадры](https://community.itsm-qa.mos.ru/service_instances/45770)

Соответствует: статус «В производстве», услуга указана.

Несоответствия:

1. **Несоответствие (Точность, подозрение):** имя компонента совпадает с именем услуги без уточнения элемента/среды. Допустимые синтаксисы предполагают «Наименование услуги + элемент/КЕ/среда» (например «… Prod», «… MOS.ITSM»).
   - **Предложение по исправлению:** переименовать компонент по одному из допустимых синтаксисов, например «АТ тест вапро. Бухгалтерия и кадры. Prod».
2. **Несоответствие (Полнота):** поле «Команда поддержки» не заполнено (контролируемое).
   - **Предложение по исправлению:** выбрать команду поддержки из справочника «Команды» в статусе «Активно», чтобы запросы по компоненту можно было переназначать с первой линии.

Примечание: стандарт требует, чтобы компонент был связан с управляемым объектом (КЕ). Наличие связи с КЕ через API не просматривается — проверить вручную в карточке компонента.

## 3. Предложения услуги

### 3.1 [АТ тест вапро. Бухгалтерия и кадры](https://community.itsm-qa.mos.ru/service_offerings/31632)

Соответствует: статус «Доступно», услуга указана.

Несоответствия:

1. **Несоответствие (Полнота):** поле «Доступность (%)» не заполнено.
   - **Предложение по исправлению:** указать числовое значение доступности (например 99.5), согласованное с клиентом в SLA.
2. **Несоответствие (Полнота):** поле «Надежность» не заполнено.
   - **Предложение по исправлению:** указать максимальное количество недоступностей в месяц (число).
3. **Несоответствие (Точность, подозрение):** имя предложения совпадает с именем услуги без уровня предложения. Допустимые синтаксисы: «Наименование услуги. Уровень предложения» / «Компонент услуги. Уровень предложения» и т.п.
   - **Предложение по исправлению:** переименовать, например «АТ тест вапро. Бухгалтерия и кадры. Стандарт».

Примечание: часы обслуживания (календарь) для предложения через API не просматриваются — проверить заполнение вручную. Целевые показатели времени реакции/решения — опциональны.

Соответствует: клиент указан, представитель клиента указан, менеджер уровня обслуживания указан, предложение и компонент услуги привязаны, покрытие выбрано.

Несоответствия:

1. **Несоответствие (Полнота):** поле «Дата начала» не заполнено.
   - **Предложение по исправлению:** указать дату начала действия соглашения; без неё SLA не сможет активироваться.
2. **Несоответствие (Точность, подозрение):** имя «АТ тест вапро. Бухгалтерия и кадры (организации и нижестоящие)» не соответствует ни одному из допустимых синтаксисов («Соглашение – Поставщик – Клиент – Компонент/Услуга» или «Поставщик – Клиент – Услуга»).
   - **Предложение по исправлению:** переименовать, например «Соглашение – <Поставщик> – <Клиент> – АТ тест вапро. Бухгалтерия и кадры».

Примечание: статус «Готовится» — допустимое значение; перед активацией проверить, что клиент, предложение и компонент активны, а менеджер уровня обслуживания имеет системную роль «Менеджер уровня услуги» (роль через API не видна).

Несоответствия:

   - **Предложение по исправлению:** переименовать по одному из допустимых синтаксисов, например «Консультирование по вопросам бухгалтерии и кадров» или «Изменение данных сотрудника».
2. **Несоответствие (Полнота):** поле «Ключевые слова» не заполнено.
   - **Предложение по исправлению:** добавить не менее трех ключевых слов для поиска шаблона.
3. **Несоответствие (Полнота):** поле «Команда» не заполнено — запрос не будет автоматически назначен.
   - **Предложение по исправлению:** выбрать команду из справочника «Команды» в статусе «Активно».
4. **Несоответствие (Полнота):** поле «Статус» не заполнено — статус запроса при регистрации не будет установлен автоматически.

Примечание: для категории «case» (Запрос на обслуживание) поле «Влияние» не требуется.

## Выводы и рекомендации

1. **Приоритет 1 (блокирует работу процесса):** у шаблона запроса не заполнены «Команда» и «Статус»; у SLA не указана «Дата начала». Без этих полей автоматическое назначение запросов и активация SLA работать не будут.
2. **Приоритет 2 (обязательные поля стандарта):** у услуги не заполнены «Описание» и «Ключевые слова»; у предложения — «Доступность (%)» и «Надежность».
3. **Приоритет 3 (приведение имен к синтаксису стандарта):** имена компонента, предложения, SLA и темы шаблона запроса требуют доработки; имя услуги — подтвердить у владельца.
4. Общие рекомендации: заполнить контролируемые поля менеджеров услуги при вводе в промышленную эксплуатацию; проверить вручную связь компонента с КЕ и часы обслуживания предложения.
